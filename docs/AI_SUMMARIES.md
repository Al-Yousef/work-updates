# Cached task summaries

Enable **AI task titles and summaries** in Queue settings. The original chat name remains above the current task title. AI changes presentation only: status, waiting owner, task identity, review state, completion fingerprints and chat routing continue to use recorded evidence.

Work Updates uses the signed-in local Codex account and an available Luna model with low reasoning effort. Each summary runs in an ephemeral read-only session with shell, apps, MCP, hooks, web search and delegation disabled. It never resumes or messages a source chat. A short recorded request excerpt and up to 3,000 characters of its latest reply are processed. This uses the account's Codex allowance; it is not an unlimited free service.

Only a recorded completed pass with loaded context is eligible. AI catches up on the current recent queue in its priority order, including cards an older version marked seen without summarizing. Reviewed, snoozed, finished, working and historical catalogue cards are skipped. Returning a completed card to the active queue makes it eligible again. Changed completed updates are queued automatically. Unchanged updates use a persistent local cache, bounded to 2,000 entries. Calls are sequential and limited to 20 per hour and 100 per rolling day. The queue footer reports current coverage, remaining work and when a budget pause will resume. Pending work survives restart; an attempted inference is never automatically repeated after a crash or an uncertain result.

The cache lives in private app data as `summary-cache.json`. Raw excerpts and credentials are not stored in the cache or diagnostic log. Disabling AI immediately uses recorded excerpts and cancels active inference. Model, authentication, network, invalid-output or cache-write failures leave the queue usable. Availability failures pause the next attempt for 15 minutes; invalid output affects only its own update and does not stall other cards. The failed update retains its recorded excerpt. **Retry failed AI summaries** in settings explicitly retries only failed current cards, within the same persistent budget. The one-shot `--retry-failed-summaries` launch flag performs the same action after the first fresh feed; it is used only for an authorized retry.

Late summaries apply only to the exact original source and completed update. A new working pass displays its recorded context until its own completed summary is available. The local diagnostic log records summary result codes and opaque cache keys, without request or response bodies.
