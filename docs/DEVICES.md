## Private connection

Install Work Updates on each computer that runs Codex. In Settings, **Your devices**, copy its pairing code using a private network address. Pair the Mac with the Windows computer, Windows with the Mac, and the iPhone with both computers. A computer continues monitoring its local chats while connected to another computer. The iPhone runs no Codex process: its requests execute on the selected computer.

For access away from home, use an existing private overlay network. [Tailscale's private device network](https://tailscale.com/docs/use-cases/personal-or-at-home-use/access-nas-media-file-servers) supports this arrangement. Install it on all three devices, sign in to the same private network, and use each computer's `100.x` address when copying its pairing code. Keep Work Updates running and its computer awake. Network installation and account sign-in are separate from app pairing; Work Updates does not open router ports, change firewall rules or provision a relay.

The connection uses pinned HTTPS, the same bounded state/command protocol as desktop pairing, and OS-protected credentials. Pairing codes grant access to a computer's queue and task commands. Disconnect a viewer to forget its saved code; revoke hosted pairing to invalidate every code for that computer. No personal data is included in public app packages.

## iPhone installation

The iPhone app is SwiftUI source in `ios/`. On a Mac with Xcode, generate its project with `ios/setup-mac.command`, open it, select your Personal Team under Signing & Capabilities, choose the connected iPhone and Run. The command never enters an Apple password or purchases a membership. Apple's [regular-account installation](https://developer.apple.com/help/account/basics/about-your-developer-account) expires after seven days and requires rebuilding/reinstalling; a paid membership supports longer distribution options.

Live phone sync runs while the app is open. When it returns to the foreground it reconnects and fetches current state. Continuous background push is not provided by a foreground connection; APNs and distribution signing require a separate configured Apple developer setup. We do not claim that an unsigned simulator app is installed on an iPhone.

## Protocol compatibility

`wu1:` codes retain the private IPv4 address, port, certificate SHA-256 pin and bearer token. Protocol v2 state adds `protocolVersion: 2`, an execution `host` identity and `servedAt`. A host's `/state` and `/events` always contain its local queue, never its merged viewer, preventing cycles and duplicate forwarding. Commands use the owner's raw IDs on the wire; namespaces exist only in the viewer. Old one-desktop codes can still be read, with a stable endpoint identity if the old host has no identity metadata.

The client never treats an uncertain POST response as permission to repeat it. Check the owner's latest chat before retrying a reply or task creation. The optional `open` command opens the exact validated Codex chat on its owning computer, rather than trying to navigate to a different computer's chat locally.
