# Scoped original-record research

Research is off until the human enables an exact existing local source. A scope names its source owner (the `source_owner` account namespace), topic, initial and incremental lookback, UTC expiry, record limit, total and daily read limits, and explicit background-read setting. This is local Codex storage access, not OAuth account verification or access to new services. The existing queue collector has its own established behavior; enabling research adds only separately scoped one-shot reads.

## Controls

- `/research`: list the newest twelve enabled scopes.
- `/research enable SOURCE_ID: JSON`: save a literal human configuration and a read-only grant. This control itself does not read. For example: `{"topic":"release review","initialLookbackSeconds":86400,"incrementalLookbackSeconds":3600,"until":"2026-10-08T18:00:00Z","maxReads":8,"maxReadsPerDay":4,"recordLimit":32,"background":false,"intervalSeconds":0}`. Choose a valid future UTC expiry within thirty days; the example date is illustrative.
- `/research read ID`: request one bounded read under the existing scope.
- `/research inspect ID`: source owner, original source revision, grant, configuration, phase, pending operation, actual attempts, cursor, latest scan and coverage, next planned read and bounded record previews. Truncation is explicit.
- `/research pause ID`, `/research resume ID`, `/research revoke ID`: control future reads. Resume cannot restore a revoked grant, widen the original scope or extend expiry. Re-enabling requires a new literal configuration and human grant. Retained private records are not deleted by revocation; revoked scopes are excluded from answer-provider context.

Initial lookback is 60 seconds to thirty days. Incremental lookback is 60 seconds to one day; after an offline gap it stays bounded and reports the missing interval. A read returns at most 64 original messages; total and rolling daily attempt limits are each 1 to 64. Explicit background reads require an interval of fifteen minutes to one day. They run only while Hyphen is open, follow rate-limit backoff, and never invoke model inference. No notification or source action is generated from a read. `research manual_only` overrides background scopes; `research off` prevents new research reads. These preferences do not create grants.

The read grant is distinct from send, write, share, execute or browser-control authority. Changing its authorization mode to `ask` holds a durable exact operation for `/authorization approve OPERATION_ID`; a subsequent read uses that same approved operation. Handoff, account revocation, changed source ownership, task identity, source store, stale collection and expiry stop the reader. Permission is checked before starting and after returning; revocation or pause during a read discards returned records. Already started bounded I/O may finish before that check, and cannot be undone.

## Originals, interpretation and gaps

The collector's one-shot reader selects exactly one active user-owned chat from the selected read-only SQLite database. It reads at most 4 MiB from that chat's recorded rollout, returns literal user and visible assistant messages, excludes analysis, tools and image contents, and starts no subscription. The database and rollout must resolve inside the selected local store. A nonce, canonical store identity, exact source, requested window, capture time and coverage envelope bind each response to its request.

Stable record hashes include original byte position and data. Later replies and corrections remain separate original records. Every read is explicitly non-exhaustive: older tail bytes, malformed/partial/oversized/undated records, concurrent file changes, excluded tools/images, count and text truncation, offline intervals and bounded deduplication remain gaps. Empty results do not establish that no work exists. Topic matching is lexical relevance; later replies are retained even when their words do not match the topic.

No deterministic assignment, overdue or completion label is inferred by the reader. When the human asks a question, the answer provider receives original evidence and coverage limits and must separate source statements from inferred interpretations and independent outcome verification. Source text that contains instructions or controls remains data. The research journal does not mutate responsibilities, commitments or write/send grants.

`research.json` allows 32 scopes, 64 actual attempts per scope, 32 recent scan records, 64 retained original records, 512 deduplication hashes, 32 human controls per scope, 5,000 replay receipts and 32 MiB. Limits refuse additional mutations. Retention windows and previews are bounded; full account history is never claimed. Cursors advance only after validated originals and a successful journal write. Failures preserve the last successful cursor. Interrupted reads pause on restart; explicit human resume is required. Corrupt, future and changed-literal-configuration journals are preserved, and older updater rollback contracts reject the new store.

`scripts/research-contract-audit.cjs --require-clean` exercises the actual scoped reader against an owned disposable SQLite/rollout store, verifies initial and later original records, read-only source hashes, stable identities, restart and revocation, with zero accounts and model calls. Packaging repeats the audit through the built collector executable on Windows and both Mac architectures. Separately authorized live reader evidence remains a distinct gate; these checks do not claim that it has happened or that the installed app changed.
