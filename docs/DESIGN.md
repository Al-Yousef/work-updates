Work Updates is a desktop queue for deciding what needs attention across many Codex chats. The notification stack is the product's main view, not a general dashboard.

Granting keyboard focus must immediately reapply taskbar exclusion. [Electron 44's Windows focus implementation](https://github.com/electron/electron/blob/v44.5.1/shell/browser/native_window_views.cc#L1333) changes the taskbar registration whenever focusability changes. Skip redundant focusability updates on repeated Open actions. Verify the native focus/skip-taskbar call sequence as well as concealed pixels, close-to-tray and observer continuity; extended window styles alone do not prove taskbar exclusion.

## Hierarchy

A card shows its source chat name and age on the first line, the task title below, a two-line excerpt of the latest recorded update, then the explicit status and waiting owner. The header uses the source chat name instead of Work Updates. Groups name the highest-attention source and show the attached chat count; the picker provides every source. Changing the picker updates the expanded chat name and device together with its task/context/action target. Excerpts are bounded to 160 characters and never add model calls or invent progress. A completed agent pass is **Ready to review**; only the user can mark the actual task **Done**. **Reviewed** acknowledges an update without closing its task. **Snooze 1h** postpones the notification.

The left device glyph is also the status indicator, in both the queue and expanded notification. It identifies the device executing the chat, not the device viewing the queue: Windows PC, Mac, Linux PC, phone or tablet when explicit source metadata exists. An unrecorded source uses a neutral device/question glyph. Local observation carries the collector host's platform; app-owned passes record their executor; paired state preserves the source identity. No hostname or credentials are displayed. A blue ring rotates around the stationary device only while Starting or Working. Waiting on you uses amber and an exclamation mark, Blocked uses coral and a stop bar, Ready to review uses green and a dot, and an external wait uses lavender and pause bars. Queued, unknown and Done use muted gray with ellipsis, question mark and check respectively. Keep the text label and explicit waiting owner, so color never carries meaning alone. Urgency stays a separate text priority. Use a 40px indicator (36px on narrow screens), preserving the notification surface. Reduced motion freezes the working arc; hidden windows pause it. Watcher refreshes update the expanded indicator without rebuilding an unchanged ring. These are Work Updates status cues within the existing Apple notification layout, not claimed Apple notification behavior.

## Controls

| Input                      | Card                             | New-task button                       |
| -------------------------- | -------------------------------- | ------------------------------------- |
| Left click / Enter / Space | Details and compact conversation | Task composer                         |
| Hold 650 ms                | Details and compact conversation | Composer with project options         |
| Right click / Shift+F10    | Same details and conversation    | Same composer with project options    |
| Escape / outside click     | Return to the queue              | Cancel composer; preserve typed draft |
| Swipe left                 | Reveal Snooze and Reviewed       | —                                     |

Click opens the full task information and compact conversation directly. Hold and context-menu gestures are optional alternatives to the same view. Open chat, Reviewed and Snooze 1h remain below the expanded content. Complete task is a separate action in Task settings, without a second checkmark. Enter sends once; Shift+Enter adds a line; composition and pending sends cannot submit again.

New tasks have a title, prompt, and optional workspace. **Queue task** saves a draft without starting inference. **Start chat** creates one conversation for that task. Starting is idempotent; retry after failure resumes the same conversation. The default task workspace is a dedicated folder. Permission prompts and blockers stay visible until answered; the app never silently accepts them.

**Complete task** moves a task to Done, with Undo and Reopen. It does not archive or delete its Codex chat. Incoming commentary never clears Done or resurrects a reviewed update. A clearly different task in an existing chat can receive a new task identity.

The compact/options images are explicitly named iOS 26; the developer example is older. They establish visible structure, not pixel-exact iOS 27 rendering. Apple's [current iPhone notification guide](https://support.apple.com/guide/iphone/view-and-respond-to-notifications-iph6534c01bc/ios) verifies hold-to-expand and quick actions. No verified current iOS 27 hold screenshot was found. Do not claim these assets demonstrate it.

Click now expands the notification directly, following the user's October 2 update. Apple normally uses tap to open the source app: our mapping is an explicit desktop adaptation. Hold 650 ms opens the same view, with press feedback and origin-based expansion, full context, a reply and actions. Right click and Shift+F10 provide the same expanded view. Escape/outside click closes and returns focus. Dragging cancels the hold; releasing a successful hold never opens a second panel. Reduced motion removes press/expansion animations.

Remove the split slate header/black body, colored status pills, always-visible per-card X, decorative fake stacks and blue/green action blocks. Underlays mean actual grouped chats only. Use a continuous frosted material and monochrome command rows. Text remains readable against the original background. Windows uses Segoe UI fallback; CSS backdrop blur approximates the material and does not implement Apple's native Liquid Glass optics.

## Queue and responsive behavior

On Windows, the target is the user's existing taskbar weather/Widgets area, as shown in their screenshot, not an added W launcher. Keep Windows' weather pixels visible. A shadowless input window with a one-step alpha background covers the first 144 DIP inside the primary taskbar strip. This is an overlay workaround, not an Explorer tile rebind; [Microsoft's Widgets API](https://learn.microsoft.com/en-us/windows/apps/design/widgets/) describes providers inside the Widgets board. Only enable the region with Widgets on, centered icons and a visible bottom taskbar; otherwise remove it to avoid covering Start or application content. Read settings without changing them and refresh on display changes and every ten seconds. Turning the feature off restores native Widgets input. macOS retains its optional corner launcher.

The weather input surface must stay above the taskbar while the pointer is inside it, without taking focus or changing the weather pixels. Use Windows' pop-up-menu level and restore its position in the native window order on hover. A regression test must raise a competing native surface over the same region, then verify Windows' actual hit target returns to the weather input window. Renderer clicks and global hover detection do not establish click interception.

The target uses a 220 ms hover dwell to open a temporary peek without stealing focus. Leaving both target and queue for 400 ms closes the peek. Clicking either retains it; dragging its header retains it and remembers the new position. Clicking the target again hides it and suppresses another hover until the pointer leaves. Dock the peek above the taskbar, preserve the previous floating position during temporary peeks, and preserve explicit hide/keyboard/tray controls. These are product-specific desktop behaviors, not Apple's Lock Screen gestures.

Launching or relaunching production starts the background companion without pinning the queue open, including with the weather shortcut disabled or unavailable. An explicit Open queue action retains it; the X hides it and leaves monitoring and the weather shortcut running. The panel X returns to the queue. All icon controls have 44px targets. Opening a panel disables the underlying native caption regions: DOM overlays and inert alone do not stop Windows intercepting their clicks as dragging. Verify the panel X has a native client hit and closes with actual Windows mouse input as well as renderer tests. A relaunch after hiding must not reveal or retain the queue. Test header dragging and weather clicks against the installed app, not just calls to its window controller.

Keep existing notification DOM, decoded icons and blur layers when visibility changes or an unchanged watcher heartbeat arrives. Only replace the queue when its visible content changes, and assemble changes before replacing it. Repeated hovers must each reveal the queue once without rebuilding unchanged cards.

Update elapsed-time labels in place. A minute boundary is not a new notification and must not reset a working ring or frosted surface. Semantic task identity belongs in the render key so a different task in the same chat refreshes the card's action target even if its wording is unchanged. Advance renderer time in the audit to verify age text changes while the same notification nodes survive.

Reveal the whole desktop surface from the left over 240 ms and reverse the same motion on dismissal. Use a transparent, shadowless native surface that stays painted after startup, with mouse input ignored while concealed; do not cycle native show/hide on hover. Concealed content is fully outside the viewport and transparent, including panels and notices. Preserve hover focus, click retention, saved drag positions and rapid direction reversal. Reduced motion reveals and conceals immediately. Verify rendered motion and transparent concealed pixels, rather than counting native show events as proof against flashing. This left-edge motion is the user's desktop requirement, not a claimed Apple gesture.

Use a 420×880 portrait notification queue, limited by the display's available height. This extends the weather preview upward while keeping its bottom anchor and gives the surface the tall, narrow silhouette of the inspected Apple Lock Screen reference. Keep the quiet Work Updates toolbar, date and clock above the notifications; give the clock 32px of top space and round the continuous outer surface to 36px. Do not add a fake notch, bezel, battery or signal indicators. A heading menu opens Updates, Queued and Done; the plus button opens the composer. At 390×590, reduce clock space and card padding while keeping titles readable and controls reachable. Expanded windows retain one readable queue column. Card titles wrap to two lines; full text is available by clicking. Long waiting-owner text wraps. Panels retain the background queue's positions while open, and replies survive dismissal. Main command targets are at least 44px; keyboard focus remains visible; collapsed settings do not participate in the dialog's Tab cycle. Verify the taller preview fits above the taskbar and all details and action controls remain reachable.

Waiting on you always sorts first, then urgent items, then other actionable blockers and review items. Ordinary working items and external waits follow. Waiting cards must identify the owner. Extract only explicit names or roles from the latest recorded response; unknown owners are labeled as unclear. Details support a named waiting owner and Automatic/Urgent/Normal priority. Group cards surface their highest-attention source, keeping every source conversation attached. Ownership and urgency changes never alter completion fingerprints or replay reviewed history.

## Required states

Loading; empty queue; queued draft; starting; active; ready to review; waiting; blocked; approval required; failed launch with retry; sync paused with last successful data; snoozed; reviewed; done; restored; disconnected companion; connected companion. Each visible control must have a verified outcome.

## Acceptance

Exercise click, hold, right click, keyboard, drag cancellation, outside dismissal, and focus return. Verify Done/Undo/Reopen, queue/start/retry, conversation send, and approvals with actual state changes. Verify that background refresh does not move the selected card. Render compact and expanded windows, long titles, empty/error states, and reduced motion. Test native Windows and macOS packages separately. Showcase images must use synthetic tasks only.
