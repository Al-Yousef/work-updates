# Continuing Hyphen chat

The native desktop interface remains the front end. Its assistant now creates one non-ephemeral Codex chat named Hyphen on the first human question and resumes that exact identity for subsequent questions and after restart. Existing local history, notes, reply targets and drafts are preserved. No model call runs at launch or on background queue updates. Existing resource defaults and account quota are unchanged.

User input is ordinary readable text; bounded current application context uses app-server `additionalContext` with untrusted provenance. Answers are natural text. Five experimental app-server dynamic tools provide connected-chat discovery, original conversation reads, related links/drafts, exact authorized Send/Queue delivery and receipt inspection. The model has no general execution, account administration or new-chat tools. Tools enforce current human authorization independently of the prompt, preserve owner/source identity, recheck task revision and use the existing durable delivery pipeline. Transport duplicates share one tool result. A completed pass never verifies the broader goal.

The local `assistant-session/session.json` records only the owned chat and pending message/turn identities. Atomic writes fence external replacement. Missing/corrupt identity, a live competing pass or unresolved acceptance holds new inference; it never creates a replacement or replays an uncertain request. Exact persisted terminal turns can reconcile after restart. An unloaded interrupted pass may be resumed without generation to reconcile its matching terminal state. The coordinator is excluded from observation and all connected-source tools, preventing self-notification and self-messaging loops.

Use the Hyphen interface for coordinated work. The stored chat can be inspected in Codex, but its dynamic tools are served by Hyphen during its own requests. Starting a turn directly in the Codex sidebar is not a supported alternate control surface. Private phone channels retain isolated ephemeral providers and do not join the desktop conversation.

Codex history and tool results follow provider storage rules; they are separate from bounded local conversation. Forget-history controls and privacy conversation removal delete the exact owned Codex chat before removing local exchanges. The next question creates a fresh identity. Unknown deletion is held rather than represented as success. Notes, original source chats, images and replay guards retain their separate scopes.

The protocol was verified against Codex `0.162.0-alpha.17.2`. Dynamic tools are experimental; an unsupported server fails visibly without falling back to an ephemeral chat. Deterministic checks: `node --test tests/assistant-session.test.cjs tests/assistant.test.cjs tests/resource-budgets.test.cjs`.

The opt-in account audit is `node scripts/persistent-assistant-live-audit.cjs --allow-disposable-chats --output=<empty-private-directory>`. Separate human authorization is required. It creates two disposable chats, uses four assistant model messages plus one worker message, proves restart recall, real tool delivery/read/status and readable stored input, then archives both. No existing personal chat is a fixture. `--resume-audit` is a narrowly checked recovery mode for the original stopped three-turn audit, using the same chats and only its two remaining model messages. Preserve failed-run evidence when recording a corrected result.

On October 11, the five-message audit passed with Luna: one continuing coordinator across restart, one worker dispatch, actual source reply relayed and receipt checked. The first three-turn attempt refused a display reference as a tool destination; after adding explicit stable source handles to application context, the same two chats completed within the original five messages. No existing personal chats were read or messaged. Cleanup is recorded separately from model/transport results.
