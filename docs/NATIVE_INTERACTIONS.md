# Native interaction completion

Issue #7 uses the existing [Messages reference](MESSAGES_REFERENCE_REBUILD.md), source-bound draft model and real native EDIT controls. The accepted default is an 880 by 660 logical canvas. A pinned panel now exposes resize edges and corners, with supported logical dimensions from 720 by 560 to 1280 by 960, further limited by the current monitor work area. The sidebar, native search/composer, wrapping, Send clearance, shortcuts and accessible bounds adapt together. Resizing cancels a held stale press and preserves the selected source, native draft, focus and selection. New sessions begin at the accepted default; this does not persist window geometry. The earlier [interaction evidence](UX_RELIABILITY_AUDIT.md) remains historical, not verification of a newly built executable.

The native palette now reads Windows' high-contrast setting and the user's paired `COLOR_WINDOWTEXT` / `COLOR_WINDOW` colors at initialization and on settings, theme and system-color changes. Custom controls, disabled labels, status text, native fields and placeholders use that pair. Filled actions and outgoing bubbles invert it; selected conversations also have a visible outline. Refreshing brushes preserves native focus, selection and draft text. This follows Microsoft's [high-contrast parameter guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/high-contrast-parameter).

`ux-audit.ps1` exercises the actual child at 96, 120, 144 and 192 DPI, including native wrap growth, Send clearance, Unicode draft restart, IME Enter protection, Shift+Enter, keyboard navigation, accessibility identity, draft ownership and delayed details. Its `-HighContrast` lane uses an isolated black/white palette without modifying Windows settings, and checks color-change draft/selection preservation before capturing the real render. Production ignores the palette override unless both isolation and an explicit audit capture are present.

## Remaining acceptance evidence

Windows text-only scaling is read from `UISettings.TextScaleFactor` and refreshed on `TextScaleFactorChanged` through an agile delegate that posts to the owned UI thread. Shutdown detaches the target before removing the subscription; the callback cannot touch rendering or EDIT controls on a background thread. A settings broadcast also refreshes the value. If the API cannot be read, the last known value is retained and the audit marks the read unavailable. This follows Microsoft's [custom-framework text-scaling guidance](https://learn.microsoft.com/en-us/windows/apps/develop/input/text-scaling).

Text scales independently of DPI from 100 to 225 percent. Native GDI fonts, DirectWrite messages and labels grow together; headers, source rows, search fields and the multiline composer reflow. Large source rows give text the icon column and keep their full names in MSAA and tooltips. The empty assistant view scrolls, image previews fit all four supported drafts while retaining at least 44 logical pixels for removal, and task menus page within the canvas with visible Previous/Next actions, Tab/Enter and Page Up/Down. Large-text reflow reserves a complete chat line even when a status notice, images and a wrapped draft share the minimum window. Native EDIT can scroll longer input within whole visible lines; status notices also reserve whole rendered lines. Full task/status text remains available through MSAA and scaled tooltips when a label is trimmed. The audit injects 150 and 225 percent into its own process without changing Windows settings, verifies real native font/field metrics and draft/source/selection/focus preservation, imports/removes four distinct image fixtures, and visits every task-menu page. Actual system-setting changes and physical screen-reader behavior remain device acceptance gates.

Keep #7 open until the source-matched integrated candidate passes physical input, clipboard/drop, real screen-reader, mixed-monitor DPI and Windows text-scale checks. The CI palette is a rendering fixture, not proof that the operating-system theme was toggled. CI resizes the actual owned HWND to narrow, expanded and default dimensions, checking native draft/selection/focus, wrapping clearance, current paint targets and MSAA bounds before capturing each render. Its explicit isolated DPI capture permits the full supported dimensions beyond the CI monitor, as the existing 192-DPI fixture already does; production retains monitor work-area limits. This is simulated resizing; physical edge dragging remains separate. Text-only fixture scaling and system API registration do not establish that the real operating-system setting was changed. No installed application or account data is changed by the CI lanes.
